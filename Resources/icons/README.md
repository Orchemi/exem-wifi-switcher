# 아이콘

EXEM Wifi Switcher 의 아이콘 자산. 메뉴바 3종과 앱 아이콘이 **같은 기하 언어**를
공유한다 — 앱 아이콘은 메뉴바가 쓰는 Wi-Fi 베이스 그대로다.

```
make-icons.py         형태 생성기. 기하가 여기 다 있다 (단일 출처)
export.sh             SVG → PNG·icns 래스터화 + 대조 시트

menubar/*.svg .png    메뉴바 상태 아이콘 3종 (템플릿 이미지)
app/tile.svg          앱 아이콘 스퀘어클 타일 실루엣
app/symbol.svg        앱 아이콘 심볼 (Wi-Fi)
app/AppIcon.icns      16~1024 전 사이즈 묶음
preview*.png          육안 확인용 대조 시트
```

SVG 도 PNG 도 전부 파생물이다. **손으로 고치지 마라.**
형태는 `make-icons.py` 의 상수를 고쳐서 바꾼다.

```bash
python3 make-icons.py && ./export.sh    # 어디서 실행해도 된다
./export.sh                             # 형태를 안 바꿨다면 이것만
```

의존성은 둘로 나뉜다. 래스터화(`export.sh`)는 **ImageMagick 7**
(`brew install imagemagick`) 과 macOS 기본 탑재 `iconutil` 만 있으면 된다.
형태 생성(`make-icons.py`)에는 **shapely** (`pip3 install shapely`) 가 더 필요하다 —
배지 둘레를 파내려면 진짜 폴리곤 불리언이 필요하고, SVG 의 fill-rule 로는 안 된다.
SVG 가 저장소에 들어 있으므로 형태를 바꿀 때만 있으면 된다.

## 1. 메뉴바 아이콘 (`menubar/`)

```
manual.svg  manual.png  manual@2x.png     사내 프로필(고정 IP) 적용 중
dhcp.svg    dhcp.png    dhcp@2x.png       DHCP(집·외부) 적용 중
error.svg   error.png   error@2x.png      전환 실패 / 헬퍼 미설치
```

접미사 없는 파일이 @1x(25x18px), `@2x` 가 50x36px 다. **정사각이 아니다** —
메뉴바가 강제하는 것은 높이(16pt)뿐이라 가로로 넓혔다. 이유는 아래 "겹침" 절에 있고,
표시 코드가 종횡비를 지켜야 한다는 점은 맨 아래 "앱에 연결하기" 절에 적었다.
macOS 는 1x·2x 두 배율만 고르므로 `@3x` 는 만들지 않는다 — 쓰이지 않는 파일이다.

파일 이름은 `build-app.sh` 와 앱 코드가 그대로 참조한다. **바꾸면 배선이 깨진다.**

### 구조 — 베이스 하나에 배지만 바뀐다

```
     Wi-Fi 아치 = 베이스(공통), 캔버스 폭의 67%
     ╭───────────────────╮
     │   ╭───────────╮   │
     │  ╭╯ ╭─────╮ ╭─┴╮  │      배지 = 상태, 캔버스의 44%
     │  ●  ╰─╮ ┌──┴───┐╯  │     manual  서류가방 — 회사
     ╰───────╯ │  배지  │      dhcp    집     — 집·외부
               └───────┘       error   원+느낌표 — 확인 필요
              (아치가 배지 뒤로 지나간다)
```

**Wi-Fi 가 주인공이고 배지는 그 위에 작게 얹힌다.** Docker 메뉴바 아이콘의 구조와
같다 — 고래가 프레임을 채우고 배지는 그 몸통 위에 작게 붙는다.

베이스가 공통이라 "Wi-Fi 설정 도구" 라는 정체는 항상 읽히고, 바뀌는 것은 배지뿐이다.
앱 아이콘(Dock)은 이 베이스만 보여주고, 메뉴바는 거기에 상태 배지를 더한다.

| 상태 | 배지 | 왜 이 형태인가 |
|---|---|---|
| `manual` | 서류가방 윤곽 | 평평한 위 + 손잡이. **집과 짝을 이룬다** |
| `dhcp` | 집 윤곽 | 낮은 지붕 + 문. 문 하나가 "건물" 이라고 말한다 |
| `error` | 원 윤곽 + 느낌표 | 시스템 상태는 배우지 않고도 읽혀야 한다 — 관례를 따른다 |

세 실루엣은 **평평함 / 뾰족함 / 둥긂** 으로 서로 가장 멀리 떨어뜨렸다 —
16px 에서 디테일이 다 죽어도 이 셋은 곁눈질로 갈린다.

### 비율 — 배지를 작게 잡는 이유

캔버스는 **50x36단위(25pt x 18pt)**. 배지는 **높이의 68.9%(24.8단위)**,
Wi-Fi 는 **폭 34.2단위** 다. 여백을 0.8단위까지 줄여 bbox 가 캔버스 세로의 **95.6%** 를 채운다.

**세로 36단위 = `pointSize` 18pt 의 @2x 픽셀 수**다. 이 둘은 반드시 같아야 한다 —
어긋나면 macOS 가 업스케일해서 흐려진다. `StatusIcons.swift` 의 `pointSize` 를 바꾸면
`make-icons.py` 의 `CANVAS_H` 도 그 두 배로 맞춰라.

실제 렌더 높이는 **17.2pt**(= 95.6% x 18pt)다. pointSize 16 / 캔버스 32 이던 시절의
15.0pt 보다 **15% 크다**.

처음에는 배지를 50% 로 잡았다. 그러면 32px 에서 배지 뜻은 잘 읽히지만
**Wi-Fi 가 좌상단 구석으로 밀려나** 도구의 정체가 약해진다. 배지는 "지금 어느 쪽인가"
만 말하면 되고, 매 순간 읽혀야 하는 것은 Wi-Fi 쪽이다. 그래서 배지를 줄였다.

Wi-Fi 크기의 상한은 취향이 아니라 **기하가 정한다.** 키울수록 정점의 점이 커지고
오른쪽으로 이동해, 어느 지점을 넘으면 배지 파냄이 그 점을 물어뜯는다.
지금 값은 그 한계 바로 아래다(여유 0.3~1.4단위). `make-icons.py` 가 매 실행마다
이 여유를 검사하고 음수면 에러를 내며 멈춘다 — 나중에 값을 만질 때 조용히 깨지지 않는다.

### 배지를 모서리에 붙이지 않는 이유 — 겹침이 이 구조의 전부다

배지를 캔버스 **우하단 모서리에 붙이면 아치 끝자락만 스친다.** 그러면 배지가 베이스
위에 얹혔다는 느낌이 안 나고, 파냄 링도 짧은 구간에만 생겨 거의 안 보인다.
그래서 모서리에서 한 칸 띄워 **아치 본체를 가로지르는 자리**에 놓았다
(그래서 아래 여백 3단위가 오른쪽 2단위보다 크다).

겹침을 늘리는 방법을 전부 실측해 비교했다. 겹침 = 배지와 그 파냄 링이
Wi-Fi 에서 지워내는 넓이의 비율이다.

**먼저 정직하게 짚어둘 것이 있다.** 오른쪽 벌림각(`SPREAD_R`)을 105° → 160° 로 늘리면
"겹침" 수치는 22% → 41% 로 뛴다. 하지만 **보이는 그림은 픽셀 하나 안 바뀐다** —
늘어난 아치는 전부 배지 뒤에 있어 그대로 잘려 나가기 때문이다(실측: 보이는 넓이
147.40 → 147.39). 수치만 부풀리는 방법이라 쓰지 않았다. 175° 를 넘기면 아치가 배지
반대편으로 다시 삐져나와 바닥에 부스러기가 생긴다.

같은 이유로, **정사각 32x32 안에서는 겹침을 23% 이상 올릴 수 없었다.**

| 방법 | 결과 |
|---|---|
| 배지를 위로 올린다 | 겹침 30% 가능하지만 배지 아래가 비어 **세로 높이가 20% 줄어든다** |
| 정사각 안에서 Wi-Fi 를 키운다 | 폭 +4% 가 한계고 겹침은 오히려 23.2% → 22.4% 로 **줄어든다**(아치 끝이 위로 올라가 배지에서 멀어진다) |
| **캔버스를 가로로 넓힌다** | **채택.** 세로 높이를 지키면서 Wi-Fi 를 키울 수 있는 유일한 축 |

캔버스 폭별 실측:

| 캔버스 | 비율 | Wi-Fi 폭 | 겹침 | 비고 |
|---|---|---|---|---|
| 32x32 | 1.00 | 21.6 | 23% | 정사각 한계 |
| **36x32** | **1.13** | **25.8** | **28%** | **채택** |
| 40x32 | 1.25 | 34.0 | 32% | 아치가 배지 반대편으로 삐져나오기 시작 |
| 44x32 | 1.38 | 42.2 | 19% | Wi-Fi 가 너무 커져 배지가 상대적으로 작아진다 |

36x32 를 골랐다 — 목표(30% 내외)에 닿으면서 정사각에서 가장 덜 벗어나고,
**세로 높이 27단위를 그대로 유지**한다(정사각안과 동일). Wi-Fi 폭은 21.6 → 25.8 로 19% 커졌다.

가로 위치는 여전히 고를 수 없다. 왼쪽은 정점의 점 배제구역, 오른쪽은 캔버스 변이라
그 사이 통로 폭이 배지 너비와 거의 같다.

### 회사 배지로 왜 서류가방인가

건물 계열(사무동 블록, 두 동짜리 스카이라인, 평지붕 타워)을 다 그려서
32px·16px 로 실제 렌더해 비교했다. 셋 다 탈락이다.

- **창문 격자는 애초에 불가능**하다. 배지 실루엣이 32px 에서 14단위, 16px 에서 7px 다
- 건물 실루엣은 16px 에서 그냥 **막대 그래프**로 읽힌다. 두 동짜리는 사이 틈이
  0.5px 라 붙어버리고, 붙고 나면 뜻 없는 L 자 조각이 된다
- 결정적으로 **집도 건물이다.** 집(뾰족 지붕) 옆에 사무동(평지붕)을 놓으면 둘 다
  "건물" 이라 한 번 더 생각해야 갈린다. 이 아이콘은 곁눈질로 읽혀야 한다

서류가방은 건물이 아니다. **집 ↔ 서류가방 = 집 ↔ 일** 은 설명이 필요 없는 짝이고,
평평한 위 + 손잡이 실루엣은 뾰족한 집과 한눈에 갈린다.

손잡이 구멍은 **깊게** 판다(위쪽 가로대가 1.5단위 남게). 얕게 파면 가로대가 1px 로
가늘어져 32px 에서 손잡이가 끊어져 보이고, 서류가방이 아니라 **콘센트 플러그**처럼
읽힌다 — 배지를 14단위로 줄이면서 실제로 겪은 문제다.

### 집 배지 — 오각형만으로는 삼각형으로 읽힌다

지붕(0.46) + 몸통짜리 민무늬 오각형을 썼더니 32px 에서 **그냥 삼각형 덩어리**로
읽혔다. 배지가 작아질수록 심해진다. 8안을 실제로 렌더해 비교했다.

| 안 | 결과 |
|---|---|
| 기본 오각형 | 삼각형 덩어리. 탈락 |
| 처마(지붕이 몸통보다 넓게) | 32px 에선 낫지만 16px 에서 처마 단차가 0.8px 로 사라진다 |
| 낮은 지붕만 | 집인지 건물인지 모를 뭉툭한 블록 |
| 처마 + 낮은 지붕 | 몸통이 좁아져 16px 에서 가느다란 기둥처럼 보인다 |
| **낮은 지붕 + 문** | **채택.** 32px·16px 모두 즉시 집으로 읽힌다 |

**문을 파낸 것이 결정적이었다.** 구멍 하나가 "이건 들어가는 곳이다 = 건물이다" 를
즉시 말해주고, 동시에 몸통 아래쪽에 무게를 실어 삼각형 인상을 깬다.
문은 32px 에서 3.6×5.3px 이고, 16px 에서도 어두운 홈으로 남는다(프리뷰에서 확인 가능).
지붕은 0.46 → 0.42 로 낮춰 몸통이 실루엣을 주도하게 했다.

경고 배지는 삼각형이 아니라 원을 골랐다. 삼각형은 뾰족해서 집과 겹친다.

### 배지 둘레를 파낸다 (knockout)

메뉴바 아이콘은 **템플릿 이미지**다. macOS 가 알파 채널만 읽고 메뉴바 배경
(라이트/다크, 강조 상태)에 맞춰 색을 알아서 칠한다. **색으로는 겹침을 구분할 수 없다.**

그래서 배지 실루엣을 2.3단위(@1x 1.15px) 부풀린 영역을 베이스에서 빼낸다. 배지 둘레에
투명 링이 생겨 배지와 아치가 한 덩어리로 뭉개지지 않는다. Docker 메뉴바 아이콘이
쓰는 방법과 같다.

그리고 이 파냄이 **구조를 만든다.** 아치의 오른쪽 벌림각을 105°까지 길게 빼서 배지
안쪽까지 이어지게 그린 다음 파냄으로 잘라낸다. 왼쪽은 48°로 두어 Wi-Fi 특유의 부채꼴을
유지한다. 잘린 자리가 배지 윤곽을 따라가므로 **아치가 배지 뒤로 지나간다**고 읽힌다 —
"Wi-Fi 가 뒤에 있고 배지가 위에 얹혀 있다".

배지가 아치를 **가로지르는** 자리에 있어야 이 링이 긴 구간에 걸쳐 보인다.
모서리로 밀면 링이 짧아져 구조 자체가 사라진다 — 위 "겹침" 절을 보라.

> 이 비대칭은 눈에 보이지 않는다. 오른쪽으로 더 뻗은 부분은 전부 잘려 없어지고,
> 남는 것은 배지 윤곽을 따라 깔끔하게 끊긴 단면뿐이다.

### 크기 기준은 32px 다 — 이전 판단을 정정한다

이전 아이콘에서는 **16px 를 최우선 기준**으로 잡았는데 과하게 보수적이었다.

메뉴바 아이콘은 16pt 이고 Retina 에서는 **@2x = 32px** 로 렌더된다. 실사용의 대부분이
32px 다. 그래서 이 아이콘은 **32px 를 주 설계 기준**으로 잡았고, 기하도 32단위 격자
위에서 그린다 — **1단위 = @2x 의 1픽셀**이라 치수를 픽셀로 직접 생각할 수 있다.
(SVG 는 `width="22" height="16"` + `viewBox="0 0 44 32"` 다.)

@1x(16px, 외장 비레티나 모니터)는 부 기준이다. **배지가 무엇인지까지 읽히지 않아도
된다** — "배지가 붙어 있다 + 셋이 서로 다르다" 까지면 충분하다(Docker 도 16px 에서는
배지 판독이 안 된다). 그 선에서 16px 를 지키려고 정한 치수가 둘 있다.

획 두께의 @1x 한계선은 위 "배지는 fill 이 아니라 line 이다" 절의 표에 정리했다.
아치를 3개로 늘리지 않는 것도 같은 이유다 — 빈틈이 1px 아래로 떨어져
@1x 에서 한 덩어리가 되기 때문이다. **지금은 3아치 + 점**이다 — 표준 Wi-Fi 글리프의
개수이고, 캔버스가 커지면서 빈틈이 @1x 1.66px 까지 확보돼 여유가 생겼다.

> 한때 2아치로 줄인 적이 있다. 캔버스가 32x32 이던 시절 3아치를 넣으면 빈틈이
> 1px 아래로 떨어졌기 때문이다. 하지만 2아치는 **점과 안쪽 아치 사이가 8단위나
> 비어** "선이 하나 빠진" 것으로 보인다(아치 사이 간격은 2.8단위였다). 캔버스를
> 키운 뒤 다시 계산해 3아치로 되돌렸다. 반지름을 상수로 박지 않고
> `arc_radii()` 가 계산하는 이유가 이것이다 — 점→아치, 아치→아치 간격을 같은
> 리듬으로 두어야 균일하게 읽힌다.

### 지켜야 할 규약

- **단색 검정 + 알파만.** 색·그라디언트·그림자를 넣으면 반전이 깨진다
- 스트로크를 쓰지 않고 전부 **아웃라인(fill path)** 으로 그렸다.
  스트로크는 크기를 바꿔도 굵기가 함께 변하지 않아 템플릿에 부적합하다
  (아치는 중심선을 buffer 해서 아웃라인으로 바꾼다)
- 코드에서 반드시 템플릿으로 표시해야 한다:

  ```swift
  let image = NSImage(named: "manual")!
  image.isTemplate = true          // 에셋 카탈로그라면 Render As: Template Image
  statusItem.button?.image = image
  ```

### 배지는 fill 이 아니라 line 이다

배지를 채우면(fill) 작아질수록 그냥 검은 덩어리가 된다. 특히 경고 배지는 **채운 원에
느낌표를 파낸** 구조라 원이 작아지면 구멍이 먼저 죽어 뭉개진다 — 실제 메뉴바에서
그 문제가 나왔다. 그래서 셋 다 **윤곽선(line)** 으로 다시 그렸다. Docker 메뉴바
아이콘과 같은 방식이다.

line 은 fill 보다 **큰 지름을 요구한다.** 획 두께 + 안쪽 여백 + 심볼이 전부 들어가야
하기 때문이다. 배지를 14 → 24.8단위로 키운 이유가 이것이다.

획 두께는 **@1x 에서 1px 이 바닥선**이다. 그 아래로 내려가면 회색 죽으로 뭉개진다.

| 요소 | 두께 | @2x | @1x |
|---|---|---|---|
| 배지 윤곽 | 2.9단위 | 2.9px | **1.45px** |
| Wi-Fi 아치 | 4.0단위 | 4.0px | 2.00px |
| 아치 사이 빈틈 | 3.32단위 | 3.3px | 1.66px |
| 점 지름 | 5.0단위 | 5.0px | 2.50px |

Wi-Fi 획은 **반지름과 분리해서** 잡는다. 반지름에 비례시키면 Wi-Fi 를 키울 때 획이
같이 굵어져 가느다란 line 배지와 무게가 어긋난다 — 실제로 한 번 4.8 대 2.4 까지
벌어져 두 요소가 다른 아이콘처럼 보였다.

배지마다 도형이 **둘** 필요하다는 점이 fill 과의 큰 차이다.

- `ink` — 실제로 그리는 윤곽선
- `mask` — 베이스에서 지워낼 **채워진** 실루엣

파냄에 `ink` 를 쓰면 배지 안쪽 빈 공간으로 Wi-Fi 아치가 비쳐 들어와 엉킨다.
반드시 `mask` 로 파내야 한다.

### 광학 무게 — line 에서는 기준이 다르다

fill 이었을 때는 세 상태의 **잉크 비율**을 0.1%p 안에 맞췄다. line 에서는 그 기준을
쓰지 않는다. 지금 잉크는 **32.1% / 33.3% / 29.1%** 로 4%p 벌어져 있다.

원이 가벼운 것은 **둘레가 짧기 때문**이고, 이건 형태의 성질이지 결함이 아니다.
같은 넓이에서 원의 둘레가 가장 짧다(집은 지붕·벽·문까지 선이 많다).
배지 지름을 키워 맞춰 보려 했지만 잉크는 오히려 **줄었다** — 배지가 커지면 파냄이
Wi-Fi 를 더 많이 지우기 때문이다(22→24단위에서 편차 4.2%p 그대로).

line 아이콘의 일관성은 잉크 총량이 아니라 **획 두께가 같은가**로 온다.
셋 다 2.6단위 한 값을 쓴다 — 그래서 나란히 놓아도 같은 계열로 읽힌다.
잉크를 억지로 맞추려면 원의 획만 굵혀야 하는데, 그건 line 스타일을 깨는 일이다.

### 확인 방법

- `preview.png` — 위쪽 묶음이 32px, 아래쪽이 16px. 각 묶음의 윗줄이 라이트 메뉴바,
  아랫줄이 다크 메뉴바다. 정수배 최근접이웃 확대라 실제 픽셀이 그대로 보인다
- `preview-menubar.png` — 다크 메뉴바 시뮬레이션. 윗줄 Retina(@2x), 아랫줄 비레티나(@1x).
  **맨 왼쪽 원·둥근사각은 이웃 아이콘 자리표시**다(macOS 기본 메뉴바 아이콘이 흔히
  차지하는 세로 14pt). 우리 것만 늘어놓으면 큰지 작은지 판단할 수 없어서 넣었다

형태를 고쳤다면 **반드시 이 두 장을 다시 보고** 32px 에서 배지가 읽히는지,
16px 에서 셋이 구분되는지 확인하라.

## 2. 앱 아이콘 (`app/`)

```
tile.svg              스퀘어클 타일 실루엣
symbol.svg            심볼 (Wi-Fi)
app-icon-1024.png     1024 마스터
AppIcon.icns          16~1024 전 사이즈 묶음
preview-app.png       256/128/64/32 대조
```

### 형태

심볼은 **메뉴바 3종이 공유하는 Wi-Fi 베이스 그대로**다. 좌우 대칭(48°)으로 그리는
것만 다르다 — 메뉴바 쪽은 오른쪽 아치를 배지 뒤로 밀어 넣지만, 앱 아이콘에는 가릴
배지가 없다.

앱은 상태가 없으므로 배지를 얹지 않는다. Dock 에는 도구의 정체만 보여주고,
상태는 메뉴바가 배지로 말한다. 체계가 그대로 드러나는 배치다.

> 이전 앱 아이콘은 핀 + 순환 화살표였다. 메뉴바가 Wi-Fi 기반으로 바뀌면서
> Dock 과 메뉴바가 서로 다른 말을 하게 되어 Wi-Fi 로 맞췄다.
> 타일 기하와 색은 그대로 둔다.

타일 기하는 짐작하지 않고 **macOS 실제 아이콘(`Terminal.app`)의 알파를 실측**해
맞췄다: 캔버스의 80.5%(1024 중 824px), 코너 반지름은 변의 24.25%,
코너 초타원 지수 2.2(2.0 이면 정원호 — 즉 아주 약한 스퀘어클이다).

심볼은 **가로 기준**으로 타일 변의 70% 를 채운다. Wi-Fi 는 가로:세로가 1.4:1 로
납작해서 긴 변 기준으로 맞추면 실제보다 작아 보인다. 질량이 위(아치)에 쏠려 있어
타일 변의 1.2% 만큼 내려 광학 중심을 맞췄다.

### 색

저채도 슬레이트 네이비 한 계열, 명도 폭이 좁은 세로 2단 그라디언트다
(`#3E4F6B` → `#232D40`). 광택·안쪽 하이라이트·바닥 그림자 같은 겹은 쓰지 않았다.
그림자는 밝은 배경에서 타일이 묻히지 않을 만큼만 넣는다.

색을 바꾸려면 `export.sh` 상단의 `GRAD_TOP` / `GRAD_BOTTOM` 을 고친다.

### 왜 생성 이미지가 아니라 벡터로 직접 그렸나

처음 앱 아이콘을 만들 때 이미지 생성 모델로 시안을 뽑아 봤지만 채택하지 않았다.
화살촉이 뭉개지고, 심볼이 중앙에서 밀려 있고, 타일이 macOS 스퀘어클이 아니었다.
셋 다 정렬을 손보는 정도로는 못 고친다 — 래스터 결과물에는 고칠 수 있는
**기하가 남아 있지 않기** 때문이다.

이번 메뉴바 재설계에서는 아예 시도하지 않았다. 배지 둘레를 정확히 2.3단위 파내고
세 상태의 잉크를 0.12%p 안에 맞추는 일은 **숫자로 표현되는 형태**에서만 가능하다.
비율을 다시 잡을 때(배지 50%→44%, Wi-Fi 확대) 아치·점·배지 박스 몇 줄을 고쳐
3종을 한 번에 다시 뽑을 수 있었던 것이 그 결과다.

## 앱에 연결하기

`scripts/build-app.sh` 가 `.app` 번들을 조립할 때 자동으로 넣는다.

- `app/AppIcon.icns` → `Contents/Resources/AppIcon.icns`,
  `Info.plist` 에 `CFBundleIconFile = AppIcon`
- `menubar/*.png` → `Contents/Resources/` 에 @1x·@2x 둘 다 복사.
  `@2x` 접미사 규칙 덕에 `NSImage(named:)` 가 화면 배율에 맞는 것을 고른다

### ⚠ 메뉴바 아이콘은 정사각이 아니다 — 코드 수정이 필요하다

아이콘은 **25pt x 18pt(@2x 50x36px)** 다. `StatusIcons.swift` 가 크기를 정사각으로
못박으면 가로가 눌린다. 또한 `pointSize` 는 캔버스 세로의 절반(18)이어야 한다 —
어긋나면 업스케일돼 흐려진다.

```swift
// Sources/ExemWifiSwitcherApp/StatusIcons.swift — 현재
image?.size = NSSize(width: pointSize, height: pointSize)   // 16 x 16 강제
```

높이만 16pt 로 맞추고 가로는 원본 비율을 따르게 고쳐야 한다.

```swift
// 이렇게
if let image, image.size.height > 0 {
    let ratio = image.size.width / image.size.height
    image.size = NSSize(width: pointSize * ratio, height: pointSize)
}
```

SF Symbols 폴백은 정사각이라 이 식으로도 그대로 16x16 이 된다 — 분기가 필요 없다.

> `pointSize` 를 다시 바꾸려면 `make-icons.py` 의 `CANVAS_H` 를 그 두 배로 맞추고
> 다시 뽑아라. 가로(`CANVAS_W`)는 구도가 정하는 값이라 함께 조정해야 한다.

### 템플릿 표시

에셋 카탈로그를 쓴다면 상태 아이콘 3종은 반드시
**Render As: Template Image** 로 지정해야 한다. 코드로 붙일 때는
`image.isTemplate = true` 를 빼먹지 마라 — 빼면 다크 메뉴바에서 검은 아이콘이
그대로 나와 보이지 않는다.
