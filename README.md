# EXEM Wifi Switcher

사내 Wi-Fi에 접속하면 고정 IP(수동 구성)로, 그 밖의 네트워크에서는 DHCP로 **자동 전환**하는 macOS 메뉴바 앱.

Wi-Fi 이름(SSID)을 보고 알아서 바꾼다. 전환할 때마다 관리자 암호를 묻지 않는다(설치할 때 한 번만 승인).

- macOS 13 이상
- **터미널을 쓰지 않는다.** 내려받아 실행하고, 앱 안에서 버튼으로 설치한다
- **서명·공증이 없다.** 그래서 처음 열 때 macOS가 한 번 막고([처음 열 때 막히는 이유](#처음-열-때-macos가-막는다)),
  새 버전으로 바꿀 때도 몇 가지가 따라온다([업데이트할 때 생기는 일](#업데이트할-때-생기는-일))
- 소스가 공개돼 있다. 직접 빌드해서 써도 된다 ([직접 빌드하기](#직접-빌드하기))

## 설치

1. **[Releases](https://github.com/Orchemi/exem-wifi-switcher/releases)에서 zip을 내려받는다**
2. 압축을 풀고 `EXEM Wifi Switcher.app` 을 **응용 프로그램** 폴더로 옮긴다
3. 앱을 연다. 처음에는 macOS가 막으므로 [아래 절차](#처음-열-때-macos가-막는다)를 한 번 거친다
4. 설정 창의 **권한** 항목에서 **[설치]** 를 누른다.
   무엇을 어디에 놓을지 먼저 보여주고, 확인하면 관리자 암호를 한 번 묻는다
5. 사내 **Wi-Fi 이름·IP·서브넷 마스크·라우터·DNS 서버** 를 입력하고 저장한다.
   **사내에서 이미 고정 IP를 쓰고 있다면 다섯 칸이 모두 채워져 있으므로** 확인하고 [저장]만 누르면 된다 —
   지금 붙어 있는 Wi-Fi 이름까지 함께 채워지므로, 그 한 번으로 자동 전환까지 선다

로그인 시 자동 실행은 설정 창의 체크상자로 켜고 끈다.
체크상자는 `~/Library/LaunchAgents` 에 항목을 놓을 뿐이고, **켜고 끄는 최종 권한은 macOS 에 있다** —
시스템 설정에서 이 항목을 끄면 로그인해도 뜨지 않는다. 앱은 그 상태를 읽을 수 없으므로,
확인하러 갈 수 있게 체크상자 옆에 **[로그인 항목 열기…]** 를 뒀다 (목록에서 `EXEM Wifi Switcher` 를 찾는다).

> 메뉴바에 아이콘이 보이지 않아도 앱은 동작 중이다. 앱을 한 번 더 실행하면 설정 창이 열린다.
> 자세한 것은 [문제 해결](#메뉴바에-아이콘이-보이지-않는다) 참조.

## 처음 열 때 macOS가 막는다

앱을 처음 열면 **"확인되지 않은 개발자"** 또는 **"손상되었습니다"** 라는 경고가 뜨고 열리지 않는다.

**왜 그런가.** Apple의 유료 개발자 프로그램(연 129,000원)에 가입하지 않아 이 앱을 **공증(notarization)** 받지 못했다.
공증이 없으면 macOS는 인터넷에서 내려받은 앱을 일단 막는다. 앱에 문제가 있어서가 아니라, Apple이 확인해 준 적이 없어서다.
숨길 일이 아니라서 그대로 적는다.

**여는 방법** (한 번만 하면 된다)

1. 앱을 열어 본다 → 경고가 뜬다 → **확인** 을 눌러 닫는다
2. **시스템 설정 > 개인정보 보호 및 보안** 을 연다
3. 아래로 내려 **보안** 항목을 찾는다. `"EXEM Wifi Switcher"이(가) 차단되었습니다` 같은 문구 옆의
   **[그래도 열기]** 또는 **[확인 없이 열기]** 를 누른다
4. 앱을 다시 연다. 한 번 더 묻는 창에서 **열기** 를 누르면 이후로는 그냥 열린다

> macOS 15(Sequoia)부터는 **아이콘을 우클릭해 여는 방법으로 넘어가지지 않는다.**
> 위의 시스템 설정 경로를 거쳐야 한다.

**믿고 열어도 되는지 확인하고 싶다면** — 이 경고를 없앨 방법이 우리에게 없으므로, 대신 확인할 거리를 둔다.

- 이 저장소의 코드를 읽는다. 특히 [`scripts/install.sh`](./scripts/install.sh) — 앱의 [설치] 버튼이 실행하는 바로 그 파일이다
- 릴리즈 노트의 **SHA-256** 과 내려받은 파일을 대조한다: `shasum -a 256 <내려받은 zip>`
- 아예 [직접 빌드](#직접-빌드하기)한다. 직접 빌드한 앱은 이 경고가 뜨지 않는다

터미널로 격리 속성을 지우는 방법(`xattr -d com.apple.quarantine`)도 있지만 권하지 않는다.
그 명령은 **모든 앱에 대해** 통하는 습관이 되기 쉽고, 정작 위험한 앱을 열 때도 손이 먼저 나가게 된다.

## 전환 권한은 앱 안에서 설치한다

IP 구성을 바꾸는 일에는 관리자 권한이 필요하다. 그 권한을 미리 등록해 두어야 전환할 때마다 암호를 묻지 않는다.

설정 창의 **권한** 항목에서 **[설치]** 를 누르면,

1. **무엇을 어디에 놓을지 먼저 보여준다.** 이 목록은 앱이 지어낸 것이 아니라
   실제로 실행할 스크립트가 `--dry-run` 으로 내놓은 내용 그대로다
2. 확인하면 관리자 암호를 **한 번** 묻는다
3. 설치가 끝나면 권한 항목이 곧바로 다시 확인된다

인증을 취소하면 아무것도 바뀌지 않는다. 실패하면 이유를 그대로 알리고, 터미널로 이어서 할 명령을 복사할 수 있게 한다.

**되돌리기** — 설치한 뒤에는 권한 항목 옆에 **[제거]** 가 나타난다. 지울 목록을 먼저 보여주고 같은 방식으로 진행한다.

> 앱이 실행하는 것은 이 저장소의 [`scripts/install.sh`](./scripts/install.sh) 다.
> 터미널에서 직접 실행하는 것과 **같은 파일**이고, 앱 번들 안(`Contents/Resources/scripts/`)에 그대로 들어 있다.
> 설치 절차를 앱이 따로 구현하지 않기 때문에 두 방법의 결과가 갈라지지 않는다.

## 회사 밖에서 먼저 설치했다면

집·카페에서 설치해도 된다. **다만 지금 채울 수 있는 값은 없다.**

- 사내 IP·서브넷·라우터·DNS는 사내에서 확인하거나 IT에 물어야 아는 값이다. 모른다고 해서
  빈 칸을 억지로 채울 일은 아니다. **[저장]은 필수 칸이 다 차고, 저장된 값과 달라졌을 때만 눌린다**
  (앞뒤 공백처럼 표기만 다른 것은 달라진 것으로 보지 않는다)
- **사내 Wi-Fi에 연결하면 값이 자동으로 채워진다.** 사내 Mac은 대개 이미 고정 IP로 구성돼 있어,
  앱이 그 값과 붙어 있는 Wi-Fi 이름까지 읽어 넣는다 — **설정 창을 열어 둔 채 연결해도 된다.**
  그 자리에서 칸이 차고 [저장]이 살아난다
- **권한 설치는 지금 해두면 된다.** 장소와 무관하다 (설정 창의 권한 섹션)
- 값을 이미 받아 뒀다면 지금 입력해도 된다 (손으로 적은 값은 자동 입력이 덮지 않는다)

그때까지 메뉴바 첫 줄은 `초기 설정하기` 로 남고 그 아래에 `- 사내 Wi-Fi 에 연결하면 채워짐` 이 붙는다.
빠뜨린 것이 있다는 뜻이 아니라, **아직 값을 만나지 못했다**는 뜻이다.

## 값이 보인다고 저장된 것은 아니다

사내에서 설정 창을 열면 앱이 **지금 시스템 구성을 읽어** 칸을 채운다. 그 값은 아직 설정 파일에
들어가지 않은 값이다 — [저장]을 눌러야 사내 프로필이 된다.

창 맨 위 한 줄이 그 둘을 갈라 준다.

| 머리말 | 뜻 |
|---|---|
| `지금 고정 IP 로 연결됨 · 아직 저장 안 됨 · …` | 지금 구성을 읽어 채운 값이다. 저장 전이다 |
| `저장된 사내 고정 IP 값 · 고치면 다음 전환부터 적용` | 설정 파일에 들어 있는 값이다 |

저장 전에는 메뉴바에도 `초기 설정하기 / - 아직 저장 안 됨` 이 남는다.

**저장을 놓치지 않게 두 자리에서 잡는다.**

- 앱에서 [설치]가 끝나면 `설치했습니다 · 한 걸음 남았습니다` 로 알리고, 그 자리에서 [값 저장]으로
  이어갈 수 있다 (저장은 관리자 인증을 한 번 더 받는다)
- 저장하지 않은 값을 둔 채 창을 닫으면 **[저장하고 닫기] · [저장 안 함] · [계속 편집]** 을 묻는다.
  [취소]로 닫을 때는 묻지 않는다 — 버리겠다고 누른 것이므로

## 설정 값 — 특히 DNS

고정 IP 프로필에는 **DNS 서버를 최소 하나 적어야 한다.** 비워 둘 수 없다.

DHCP는 IP뿐 아니라 DNS 서버 주소도 함께 알려준다. 고정 IP는 그렇지 않다. DNS를 비워 두면 이 도구가
시스템의 DNS 설정을 지우게 되고, 그러면 IP는 붙어 있는데 **주소가 하나도 열리지 않는다.**
"인터넷이 안 된다"로 보이는 그 상태다. 그래서 빈 DNS는 저장 단계에서 거부한다.

사내 DNS 서버 주소는 보통 사내에서 DHCP로 연결했을 때의 값과 같다. 확인하는 법:

```bash
networksetup -getdnsservers Wi-Fi      # 지금 설정된 값
```

사내에서 이미 고정 IP를 쓰고 있다면 설정 창이 현재 값을 채워 준다. **읽지 못했을 때는 빈 칸으로
두지 않고 그 사실을 칸 아래에 적는다** — 읽지 못한 것을 "없음"으로 오해해 저장하는 일이 없어야 한다.

여러 개면 쉼표로 나눈다 (최대 8개, IPv4만).

## 설정을 저장할 때 관리자 인증을 한 번 받는다

설정 파일은 `root:wheel 0644` 다. 사용자 권한으로는 고칠 수 없다.

**왜 잠그는가.** 이 파일의 `dns`·`router` 값은 암호 없이 실행되는 `apply` 를 통해 그대로 root의
`networksetup` 인자가 된다. 파일을 사용자 권한으로 고칠 수 있으면, **암호를 모르는 채 당신 계정으로
실행되는 코드**(내려받은 앱·스크립트)가 시스템 DNS를 공격자 서버로, 기본 게이트웨이를 LAN 안의
다른 기기로 바꿀 수 있다. 이 도구를 설치하기 전에는 두 작업 모두 관리자 인증을 요구했다.
설치 때문에 그 요구가 사라지면 안 된다.

- **저장할 때만** 인증 창이 뜬다. 온보딩과 값을 바꿀 때뿐이라 실질적으로 몇 번 되지 않는다
- **전환할 때는 묻지 않는다.** 이 도구의 존재 이유가 거기에 있다
- 인증을 취소하면 **저장되지 않고 이전 설정이 그대로 남는다.** 창이 그 사실과 함께,
  터미널에서 이어서 저장할 명령을 알려 준다
- **관리자 계정이 아니면 저장할 수 없다.** 인증 창을 띄우기 전에 알려 준다

저장을 처리하는 스크립트(`save-config`)는 **`sudoers` 에 넣지 않는다.** 넣으면 파일을 잠근 의미가 사라진다.
설치 스크립트가 마지막에 이 조건을 확인해 보여 준다.

## 설치되는 항목 전부

이 도구는 `sudoers` 를 수정하고 로그인 항목을 등록한다. 무엇이 어디에 놓이는지 숨기지 않는다.

| 경로 | 소유·권한 | 무엇 |
|---|---|---|
| `/usr/local/libexec/exem-wifi-switcher/` | `root:wheel 0755` | 아래 두 스크립트를 담는 디렉터리 |
| `/usr/local/libexec/exem-wifi-switcher/apply` | `root:wheel 0755` | `networksetup` 을 호출하는 유일한 스크립트. 인자는 프로필 이름 하나뿐이고 화이트리스트로 검증한다. **암호 없이 실행된다** |
| `/usr/local/libexec/exem-wifi-switcher/save-config` | `root:wheel 0755` | 설정 파일을 제자리에 놓는 스크립트. **암호 없이 실행되지 않는다** — 저장할 때 관리자 인증을 받는다 |
| `/etc/sudoers.d/exem-wifi-switcher` | `root:wheel 0440` | 위 `apply` 만 암호 없이 실행하도록 허용. 와일드카드를 쓰지 않고 **인자 패턴을 길이별로 고정**해 나열한다. `save-config` 는 여기 없다 |
| `/usr/local/etc/exem-wifi-switcher/` | `root:wheel 0755` | 설정 디렉터리 |
| `/usr/local/etc/exem-wifi-switcher/config.json` | `root:wheel 0644` | 사용자 설정. 사내 IP 값이 여기에만 저장되고 저장소에는 올라가지 않는다 |
| `~/Library/LaunchAgents/com.horbis.exem-wifi-switcher.agent.plist` | 사용자 | 로그인 시 자동 실행(선택). 설정 창에서 켤 때만 생긴다 |
| `~/Library/Preferences/com.horbis.exem-wifi-switcher.plist` | 사용자 | 앱이 남기는 설정값(자동 전환 on/off 등). 앱이 만든다 |

상위 디렉터리(`/usr/local`, `/usr/local/libexec`, `/usr/local/etc`)가 없으면 `root:wheel 0755` 로 만든다.
이미 있으면 건드리지 않는다.

이미 설정 파일이 있으면 **내용은 그대로 두고 소유·권한만 위 값으로 맞춘다.**
(예전 버전은 `root:admin 0664` 로 놓았다. 그 상태에서는 admin 그룹의 아무 프로세스나 값을 바꿀 수 있다)

앱 자체(`EXEM Wifi Switcher.app`)는 사용자가 둔 자리에 그대로 있다. 설치가 앱을 옮기지 않는다.

**완전 제거**

설정 창의 권한 항목 옆 **[제거]** 를 누른다. 지울 목록을 먼저 보여주고, 관리자 인증을 한 번 받는다.

터미널로 하려면:

```bash
./scripts/uninstall.sh            # 아래 항목을 되돌리고 정말 사라졌는지 검증한다
./scripts/uninstall.sh --dry-run  # 무엇을 지울지 먼저 보기
```

제거가 하는 일 — 로그인 항목 · `sudoers` 규칙 · 권한 스크립트 두 개 · 설정 디렉터리 ·
앱 설정값(`~/Library/Preferences/…`) · 위치 권한 기록(`tccutil reset Location`).
터미널로 실행하면 실행 중인 앱도 종료한다 (앱에서 누른 경우에는 결과를 볼 수 있도록 종료하지 않는다).

**제거해도 남는 것** (직접 정리한다)

- **앱 자체** — 응용 프로그램 폴더에서 `EXEM Wifi Switcher.app` 을 휴지통으로 옮긴다
- **알림 권한** — **시스템 설정 > 알림**에서 `EXEM Wifi Switcher` 항목을 지운다.
  macOS는 이것을 명령으로 지우는 방법을 제공하지 않는다
- `/usr/local/libexec` · `/usr/local/etc` — 이 도구가 만들었더라도 다른 도구가 쓸 수 있어 남긴다

## 업데이트할 때 생기는 일

새 버전으로 바꾸면 두 가지가 따라온다. **둘은 같은 이유에서 나온다** — 이 앱에는 서명·공증이 없어서
([처음 열 때 macOS가 막는다](#처음-열-때-macos가-막는다) 와 같은 이유) 빌드할 때마다 코드 서명이 달라지고,
macOS는 새 앱을 **이름만 같은 다른 앱**으로 본다. 앱에 문제가 생긴 것이 아니다.

**1. 위치 권한을 다시 허용해야 한다**

Wi-Fi 이름을 읽지 못하게 되고, 메뉴 머리말이 `초기 설정하기` 로, 그 아래가 `- 위치 권한 미승인` 으로 바뀐다.
설정 창의 **권한** 항목에서 **[허용 요청]** 을 누르면 승인 창이 다시 뜬다
(한 번 거부한 뒤라면 **[위치 권한 열기…]** 로 시스템 설정에서 켠다). 그 한 번으로 원래대로 돌아간다.

**나머지는 그대로다.** 알림 권한은 앱의 **번들 식별자**에 매여 있어 남고,
전환 권한과 설정 값은 앱 밖(`/usr/local/…`)에 있어 앱을 바꿔도 영향이 없다.
**위치 권한만 앱의 서명에 매여 있다.**

**2. "백그라운드에서 실행될 수 있습니다" 알림이 한 번 뜬다**

로그인 항목을 켜 둔 상태로 앱을 바꾸면 macOS가
**"'EXEM Wifi Switcher' 앱은 백그라운드에서 실행될 수 있습니다"** 라는 알림을 띄운다.
새 앱이 로그인 항목에 등록된 것으로 보기 때문이다. **macOS가 하는 정상 안내이므로 무시해도 된다** —
자동 실행이 꺼지지는 않는다. 확인하고 싶으면 알림을 눌러
**시스템 설정 > 일반 > 로그인 항목 및 확장 프로그램**에서 `EXEM Wifi Switcher` 가 켜져 있는지 보면 된다.

> 직접 빌드해서 쓰는 경우에도 똑같다. `./scripts/build-app.sh` 로 다시 만든 앱은 서명이 달라지므로
> 위치 권한을 다시 허용해야 한다.

## 자동 전환

메뉴의 **자동 전환** 항목으로 켜고 끈다. 기본값은 켜짐이다.
(초기 설정이 끝나기 전에는 이 항목이 보이지 않는다 — 전환할 프로필도, 판단할 Wi-Fi 이름도 없어
켜고 끌 의미가 없기 때문이다. 설정을 마치면 원래 값 그대로 다시 나타난다)

- 접속한 Wi-Fi 이름이 프로필의 `ssids` 목록에 있으면 그 프로필을, 없으면 기본 프로필(보통 DHCP)을 적용한다
- 전환하면 **알림으로 알린다** — 알림을 허용한 경우다. 거부했다면 알림은 뜨지 않고 전환 내역은 메뉴에만 남는다
  (메뉴의 자동 전환 아래에 `- 알림 꺼짐` 이 뜨고, 바로 아래 **"알림 설정 열기…"** 로 갈 수 있다)
- 이미 목표 구성이면 아무것도 하지 않는다. **IP·서브넷·라우터뿐 아니라 DNS도 함께 본다** —
  IP만 맞고 사내 DNS가 남아 있으면 아직 적용된 것이 아니다 (DNS를 읽지 못한 경우는 판정에서 뺀다)
- 한 번 맞춰진 뒤 구성이 다시 어긋나면(시스템 설정에서 직접 바꿈·다른 도구·macOS 업데이트) **다시 적용한다**
- 전환에 실패하면 간격을 늘려 가며 다시 시도하고(10초 → 30초 → 90초 → 270초), 다섯 번 연속 실패하면 멈춘다.
  Wi-Fi가 바뀌면 다시 시도한다. 같은 자리에서 원인을 고쳤다면 메뉴의 **"지금 다시 시도"** 를 누르거나 자동 전환을 껐다 켠다
- 메뉴에서 **직접 다른 프로필을 고르면** 그 Wi-Fi에 머무는 동안 자동 전환이 되돌리지 않는다. 다른 Wi-Fi로 옮기면 자동으로 돌아간다
- **Wi-Fi 이름을 읽지 못하면 구성을 건드리지 않는다.** 어디에 있는지 모르는 채로 IP를 바꾸는 것보다 그대로 두는 편이 안전하다

전환할 Wi-Fi 이름은 설정 창의 **사내 Wi-Fi 이름** 칸에 적는다 (설정 파일의 `profiles[].ssids` 에 저장된다).

- 사내에서 처음 열면 **지금 붙어 있는 Wi-Fi 이름이 채워져 있다** (고정 IP로 연결돼 있을 때만 — 그 자리가 곧 그 프로필을 쓸 자리다)
- **등록하는 이름은 하나다.** 게스트망은 개방망이라 고정 IP를 쓸 이유가 없다 — 고정 IP가 필요한
  사내 Wi-Fi 하나만 등록한다
- 사내(고정 IP로 연결된 상태)에서는 이 칸이 **잠긴다.** 앱이 읽어 넣은 이름이라 손댈 이유가 없고,
  실수로 고치면 값이 다 맞아도 자동 전환만 조용히 걸리지 않는다.
  잠긴 칸은 **테두리 없이 값만** 보인다 (적는 칸이 아니라는 뜻이다)
- **사외(DHCP)에서는 잠기지 않는다.** 사외에서 처음 설정하는 사람이 이름을 넣을 자리이자,
  잘못 넣은 이름을 고칠 자리다
- **비워 두면 자동 전환이 이 프로필을 고르지 못한다.** 값이 다 맞아도 기본 프로필(DHCP)로 떨어지므로,
  사내에서 고정 IP가 풀리는 것으로 보인다. 메뉴에서 직접 고르는 쓰임만 남는다
- DHCP로 연결된 상태(사외)에서는 채우지 않는다 — 지금 붙어 있는 Wi-Fi가 사내라는 근거가 없고,
  집·카페 이름이 사내 프로필에 박히면 **그 자리에서 사내 고정 IP가 걸린다**

## 위치 권한이 필요한 이유

macOS는 **Wi-Fi 이름(SSID)을 위치 정보로 취급한다.** 권한이 없으면 이름을 읽을 수 없고, 그러면 여기가 사내인지 밖인지 판단할 방법이 없다.
(`ipconfig`·`system_profiler` 는 권한과 무관하게 `<redacted>` 만 돌려준다)

**이 권한은 초기 설정의 필수 항목이다.** 없으면 사내 Wi-Fi 이름을 손으로 적어 넣어야 하는데,
오타 하나면 자동 전환이 조용히 걸리지 않는다. 그래서 갖춰지기 전까지 메뉴 머리말이 **초기 설정하기**로 남는다.

- 첫 실행에서 승인 창이 한 번 뜬다. 위치는 이 판단에만 쓰이고 저장하거나 외부로 보내지 않는다
- 허용하면 설정 창의 **사내 Wi-Fi 이름** 칸이 지금 붙어 있는 이름으로 채워진다. 아직 안 물었다면
  그 칸 옆의 [위치 권한 허용] 을 누르면 된다
- 거부하면 자동 전환이 동작하지 않는다. 그 사실은 메뉴에 표시되고 알림으로도 한 번 알린다
- 나중에 켜려면: 설정 창의 **권한** 섹션에서 [허용 요청] 또는 [위치 권한 열기…] 를 누른다.
  아직 묻지 않은 상태라면 승인 창이 바로 뜨고, 한 번 거부했다면 **시스템 설정 > 개인정보 보호 및 보안 >
  위치 서비스** 가 열린다. 이 화면은 앱 목록이라 앱을 지목해서 열 수 없다 —
  **이름순** 목록에서 `EXEM Wifi Switcher` 를 찾아 켠다
- **필수라고 해서 앱이 잠기지는 않는다.** 권한 없이도 메뉴에서 프로필을 골라 **수동 전환**하는 것은 그대로 된다

## 문제 해결

### 권한이 갖춰졌는지 확인한다

설정 창의 **권한** 섹션이 필요한 권한 넷(전환·설정 저장·위치·알림)을 한자리에 모아 보여준다.
항목마다 지금 상태와 왜 필요한지가 적혀 있고, 갖춰지지 않은 항목에는 조치가 붙는다 —
설치가 필요하면 **[설치]**, 시스템 권한이면 **[설정 열기]**.

창을 열 때와 다른 앱에 다녀와 돌아올 때마다 다시 확인하므로, 시스템 설정에서 허용하고
돌아오면 그대로 반영된다. 같은 내용을 터미널에서 보려면 `--diagnose` 를 쓴다 (판정은 같다).

### 메뉴바에 아이콘이 보이지 않는다

macOS 26 + 노치가 있는 MacBook에서 **메뉴바 자리가 부족하면** 새 상태 항목이 노치 뒤로 밀려 그려지지 않는 경우가 있다.
앱은 정상 동작 중이고 자리만 없는 상태다. 해볼 수 있는 것:

- 쓰지 않는 메뉴바 아이콘을 몇 개 정리한다 (앱 설정에서 끄거나 제거)
- `⌘` 를 누른 채 메뉴바 아이콘을 드래그해 순서를 바꾼다. 왼쪽으로 옮기면 노치를 피할 수 있다
- 외부 모니터(노치 없음)에서는 정상적으로 보일 가능성이 높다
- Ice·Bartender 같은 메뉴바 관리 앱으로 자리를 확보한다

**메뉴바가 유일한 출입구는 아니다.** 아이콘이 보이지 않아도 아래로 접근할 수 있다.

- **앱을 한 번 더 실행하면** 이미 떠 있는 앱의 설정 창이 열린다 (Launchpad·Spotlight 로 다시 열면 된다)
- 터미널을 쓸 수 있다면 상태를 그대로 찍어 볼 수 있다

```bash
# 지금 상태 확인 (Wi-Fi 이름이 읽히는지 · 자동 전환이 무엇을 하려는지)
"/Applications/EXEM Wifi Switcher.app/Contents/MacOS/EXEM Wifi Switcher" --diagnose
```

### 전환이 실패한다

메뉴에 실패 이유가 남는다. 흔한 원인은 둘이다.

- `sudo: a password is required` — 권한 설치가 안 됐거나 풀렸다. 설정 창의 **[설치]** 를 다시 누른다
- 고정 IP 프로필의 DNS가 비어 있다 — 전환을 하지 않고 멈춘다. 설정 창에서 DNS 서버를 채운다
  (비운 채로 적용하면 이름 해석이 끊기므로, 적용하지 않는 쪽이 안전하다)

### 설정을 저장하지 못한다

- **인증을 취소했다** — 저장되지 않았고 이전 설정이 그대로다. 다시 저장하면 된다
- **관리자 계정이 아니다** — 설정 파일은 `root:wheel` 소유라 관리자 계정에서만 저장할 수 있다.
  관리자 계정으로 로그인하거나, 관리자에게 `sudo nano /usr/local/etc/exem-wifi-switcher/config.json` 을 요청한다
- **전환 권한을 아직 설치하지 않았다** — 저장을 처리할 스크립트가 없다. 인증 창을 띄우기 전에 알려 준다.
  설정 창의 권한 항목에서 **[설치]** 를 누른다
- **이 Mac을 여러 계정이 쓴다** — `sudoers` 규칙은 설치를 실행한 계정 하나만 허용한다.
  다른 계정에서 다시 설치하면 이전 계정의 무암호 전환이 끊긴다 (그 계정에서 다시 설치하면 복구된다)

macOS를 크게 업데이트하면 `/usr/local` 아래 항목이나 sudoers 규칙이 정리될 수 있다.
설정 창의 권한 섹션(또는 `--diagnose`)에서 "전환 권한" 이 `설치되지 않음` · `무암호 규칙 없음` 이면
**[설치]** 를 다시 누르면 된다.

### 전환 알림이 뜨지 않는다

**시스템 설정 > 알림**에서 `EXEM Wifi Switcher` 를 허용한다.
메뉴의 "알림 설정 열기…" 는 **이 앱의 알림 화면을 바로 연다** — 긴 앱 목록을 훑을 필요가 없다.
`--diagnose` 의 "알림 권한" 줄이 지금 상태를 알려준다.

알림이 없어도 전환은 그대로 동작한다. 다만 **IP가 바뀐 사실을 그 자리에서 알 방법이 사라지므로**,
거부된 상태는 메뉴에 상시 표시된다. 무슨 일이 있었는지는 메뉴(와 `--diagnose`)에 남는다.

### Wi-Fi 이름을 읽지 못한다

`--diagnose` 의 "위치 권한" 줄을 본다.

- `거부됨` — 시스템 설정에서 허용한다
- `아직 묻지 않음` — 앱을 실행하면 승인 창이 뜬다. **방금 새 버전으로 바꿨다면 이 상태가 된다**
  ([업데이트할 때 생기는 일](#업데이트할-때-생기는-일))
- 승인했는데도 이름이 비어 있으면 시스템 전체 **위치 서비스**가 꺼져 있는 경우다

권한이 없는 동안에는 설정 창의 **사내 Wi-Fi 이름** 칸이 자동으로 채워지지 않는다.
그 사실이 칸 아래에 표시되며, 이름을 알고 있다면 직접 입력해도 된다.

## 직접 빌드하기

Releases 의 앱을 쓰지 않고 직접 만들어도 된다. **Xcode는 필요 없다** — Command Line Tools만 있으면 된다.

```bash
xcode-select --install     # 아직 없다면
git clone https://github.com/Orchemi/exem-wifi-switcher.git
cd exem-wifi-switcher

./scripts/build-app.sh     # dist/EXEM Wifi Switcher.app 조립 (시스템을 바꾸지 않는다)
open dist                  # 앱을 응용 프로그램 폴더로 옮기고 실행한다
```

직접 빌드한 앱은 인터넷에서 내려받은 것이 아니므로 [Gatekeeper 경고가 뜨지 않는다](#처음-열-때-macos가-막는다).

전환 권한 설치는 앱의 **[설치]** 버튼으로 하면 되고, 터미널을 선호하면 같은 일을 이렇게 할 수 있다.

```bash
./scripts/install.sh              # 하는 일을 먼저 보여주고 확인을 받는다
./scripts/install.sh --dry-run    # 무엇을 할지만 보기
./scripts/uninstall.sh            # 되돌리기
```

## 한계

- IPv4만 다룬다. IPv6 구성은 건드리지 않는다
- **서명·공증이 없다.** 내려받은 앱은 처음 열 때 한 번 막히고, 시스템 설정에서 허용해야 한다.
  새 버전으로 바꿀 때마다 위치 권한을 다시 허용해야 한다 ([업데이트할 때 생기는 일](#업데이트할-때-생기는-일))
- Wi-Fi 이름이 같은 다른 네트워크는 구분하지 못한다 (BSSID를 보지 않는다)
- 고정 IP 프로필은 DNS 서버를 반드시 지정해야 한다 (비워서 DHCP DNS를 물려받을 수 없다)
- 설정을 바꿀 때마다 관리자 인증이 필요하다. 관리자 계정이 아니면 저장할 수 없다
- **Intel Mac에서 Homebrew가 `/usr/local` 을 소유하고 있으면 설치할 수 없다.**
  `sudo` 는 규칙에 적힌 경로를 그대로 실행하므로, 그 경로를 사용자 권한으로 갈아 끼울 수 있으면
  임의의 코드가 무암호로 root 실행된다. 설치 스크립트는 이 상태를 감지하고 멈춘다.

  이때 **`sudo chown root:wheel /usr/local` 을 실행하지 마라.** Homebrew가 통째로 망가지고
  `brew` 로는 되돌릴 수 없다. Apple Silicon의 Homebrew는 `/opt/homebrew` 를 쓰므로 이 문제가 없다
