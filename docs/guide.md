## 설정하기

### 값이 보인다고 저장된 것은 아닙니다

사내에서 설정 창을 열면 앱이 **지금 시스템 구성을 읽어** 칸을 채웁니다. 그 값은 아직 설정 파일에
들어가지 않은 값입니다. **[저장]** 을 눌러야 사내 프로필이 됩니다.

창 맨 위 한 줄이 그 둘을 갈라 줍니다.

| 머리말 | 뜻 |
|---|---|
| `지금 고정 IP 로 연결됨 · 아직 저장 안 됨 · …` | 지금 구성을 읽어 채운 값입니다. 저장 전입니다 |
| `저장된 사내 고정 IP 값 · 고치면 다음 전환부터 적용` | 설정 파일에 들어 있는 값입니다 |

저장 전에는 메뉴바에도 `초기 설정하기 / - 아직 저장 안 됨` 이 남습니다.

**저장을 놓치지 않도록 두 자리에서 잡습니다.**

- 앱에서 **[설치]** 가 끝나면 `설치했습니다 · 한 걸음 남았습니다` 로 알리고, 그 자리에서 **[값 저장]** 으로
  이어갈 수 있습니다 (저장은 관리자 인증을 한 번 더 받습니다)
- 저장하지 않은 값을 둔 채 창을 닫으면 **[저장하고 닫기]** · **[저장 안 함]** · **[계속 편집]** 을 묻습니다.
  **[취소]** 로 닫을 때는 묻지 않습니다. 버리겠다고 누르신 것이기 때문입니다

### 설정 값과 DNS

고정 IP 프로필에는 **DNS 서버를 최소 하나 적어야 합니다.** 비워 둘 수 없습니다.

DHCP는 IP뿐 아니라 DNS 서버 주소도 함께 알려줍니다. 고정 IP는 그렇지 않습니다. DNS를 비워 두면
이 도구가 시스템의 DNS 설정을 지우게 되고, 그러면 IP는 붙어 있는데 **주소가 하나도 열리지 않습니다.**
"인터넷이 안 된다"로 보이는 그 상태입니다. 그래서 빈 DNS는 저장 단계에서 거부합니다.

사내 DNS 서버 주소는 보통 사내에서 DHCP로 연결했을 때의 값과 같습니다. 확인하는 방법입니다.

```bash
networksetup -getdnsservers Wi-Fi      # 지금 설정된 값
```

사내에서 이미 고정 IP를 쓰고 계시다면 설정 창이 현재 값을 채워 줍니다. **읽지 못했을 때는 빈 칸으로
두지 않고 그 사실을 칸 아래에 적습니다.** 읽지 못한 것을 "없음"으로 오해해 저장하는 일이 없어야 하기 때문입니다.

DNS 서버가 여러 개면 쉼표로 나눕니다 (최대 8개, IPv4만).

### 저장할 때 관리자 인증을 한 번 받습니다

설정 파일은 `root:wheel 0644` 입니다. 사용자 권한으로는 고칠 수 없습니다.

**왜 잠그는가요.** 이 파일의 `dns`·`router` 값은 암호 없이 실행되는 `apply` 를 통해 그대로 root의
`networksetup` 인자가 됩니다. 파일을 사용자 권한으로 고칠 수 있으면, **암호를 모르는 채 사용자 계정으로
실행되는 코드**(내려받은 앱이나 스크립트)가 시스템 DNS를 공격자 서버로, 기본 게이트웨이를 LAN 안의
다른 기기로 바꿀 수 있습니다. 이 도구를 설치하기 전에는 두 작업 모두 관리자 인증을 요구했습니다.
설치 때문에 그 요구가 사라지면 안 됩니다.

- **저장할 때만** 인증 창이 뜹니다. 처음 설정할 때와 값을 바꿀 때뿐이라 실질적으로 몇 번 되지 않습니다
- **전환할 때는 묻지 않습니다.** 이 도구의 존재 이유가 거기에 있습니다
- 인증을 취소하면 **저장되지 않고 이전 설정이 그대로 남습니다.** 창이 그 사실과 함께,
  터미널에서 이어서 저장할 명령을 알려 줍니다
- **관리자 계정이 아니면 저장할 수 없습니다.** 인증 창을 띄우기 전에 알려 줍니다

저장을 처리하는 스크립트(`save-config`)는 **`sudoers` 에 넣지 않습니다.** 넣으면 파일을 잠근 의미가
사라집니다. 설치 스크립트가 마지막에 이 조건을 확인해 보여 줍니다.

## 자동 전환

메뉴의 **자동 전환** 항목으로 켜고 끕니다. 기본값은 켜짐입니다.
초기 설정이 끝나기 전에는 이 항목이 보이지 않습니다. 전환할 프로필도, 판단할 Wi-Fi 이름도 없어
켜고 끌 의미가 없기 때문입니다. 설정을 마치면 원래 값 그대로 다시 나타납니다.

- 접속한 Wi-Fi 이름이 프로필의 `ssids` 목록에 있으면 그 프로필을, 없으면 기본 프로필(보통 DHCP)을 적용합니다
- 전환하면 **알림으로 알립니다.** 알림을 허용하신 경우입니다. 거부하셨다면 알림은 뜨지 않고 전환 내역은
  메뉴에만 남습니다 (메뉴의 자동 전환 아래에 `- 알림 꺼짐` 이 뜨고, 바로 아래 **"알림 설정 열기…"** 로 갈 수 있습니다)
- 이미 목표 구성이면 아무것도 하지 않습니다. **IP·서브넷·라우터뿐 아니라 DNS도 함께 봅니다.**
  IP만 맞고 사내 DNS가 남아 있으면 아직 적용된 것이 아닙니다 (DNS를 읽지 못한 경우는 판정에서 뺍니다)
- 한 번 맞춰진 뒤 구성이 다시 어긋나면(시스템 설정에서 직접 바꿈, 다른 도구, macOS 업데이트) **다시 적용합니다**
- **전환 권한이 갖춰지지 않았으면 아예 시도하지 않습니다.** `apply` 스크립트나 무암호 규칙이 빠진
  상태에서는 결과가 뻔합니다. 메뉴가 전환을 잠그는 상태와 같은 상태입니다. 그 사실을 메뉴에 적어 둘 뿐
  실패를 쌓지 않습니다. 권한을 다시 설치하면 다음 확인에서 바로 되살아납니다
- 전환에 실패하면 간격을 늘려 가며 다시 시도하고(10초 → 30초 → 90초 → 270초), 다섯 번 연속 실패하면 멈춥니다.
  Wi-Fi가 바뀌면 다시 시도합니다. 같은 자리에서 원인을 고치셨다면 메뉴의 **"지금 다시 시도"** 를 누르거나
  자동 전환을 껐다 켜시면 됩니다
- **켜져 있는 동안에는 메뉴에서 프로필을 고를 수 없습니다.** 항목은 그대로 보이고 지금 적용된 것에
  체크도 서 있지만, 눌리지는 않습니다. 자동이 곧 되돌릴 선택이기 때문입니다.
  손으로 다른 프로필을 쓰시려면 **자동 전환을 끄고 고릅니다.** 다시 켜면 그 자리에 맞는 프로필로 돌아갑니다
- **Wi-Fi 이름을 읽지 못하면 구성을 건드리지 않습니다.** 어디에 있는지 모르는 채로 IP를 바꾸는 것보다
  그대로 두는 편이 안전합니다
- **위치 권한이 없으면 자동 전환이 동작하지 않습니다.** macOS가 Wi-Fi 이름을 위치 정보로 취급하기
  때문입니다 ([이 앱이 요구하는 권한](../README.md#이-앱이-요구하는-권한)). 그 사실은 메뉴에 표시되고
  알림으로도 한 번 알립니다

전환할 Wi-Fi 이름은 설정 창의 **사내 Wi-Fi 이름** 칸에 적습니다 (설정 파일의 `profiles[].ssids` 에 저장됩니다).

- 사내에서 처음 열면 **지금 붙어 있는 Wi-Fi 이름이 채워져 있습니다** (고정 IP로 연결돼 있을 때만입니다.
  그 자리가 곧 그 프로필을 쓸 자리이기 때문입니다). 위치 권한을 아직 안 물은 상태라면
  그 칸 옆의 **[위치 권한 허용]** 을 누르시면 됩니다
- **등록하는 이름은 하나입니다.** 게스트망은 개방망이라 고정 IP를 쓸 이유가 없습니다.
  고정 IP가 필요한 사내 Wi-Fi 하나만 등록합니다
- 사내(고정 IP로 연결된 상태)에서는 이 칸이 **잠깁니다.** 앱이 읽어 넣은 이름이라 손댈 이유가 없고,
  실수로 고치면 값이 다 맞아도 자동 전환만 조용히 걸리지 않습니다.
  잠긴 칸은 **테두리 없이 값만** 보입니다 (적는 칸이 아니라는 뜻입니다)
- **사외(DHCP)에서는 잠기지 않습니다.** 사외에서 처음 설정하시는 분이 이름을 넣을 자리이자,
  잘못 넣은 이름을 고칠 자리입니다
- **비워 두면 자동 전환이 이 프로필을 고르지 못합니다.** 값이 다 맞아도 기본 프로필(DHCP)로 떨어지므로,
  사내에서 고정 IP가 풀리는 것으로 보입니다. 메뉴에서 직접 고르는 쓰임만 남습니다
- DHCP로 연결된 상태(사외)에서는 채우지 않습니다. 지금 붙어 있는 Wi-Fi가 사내라는 근거가 없고,
  집이나 카페 이름이 사내 프로필에 박히면 **그 자리에서 사내 고정 IP가 걸립니다**

## 회사 밖에서 먼저 설치했다면

집이나 카페에서 설치하셔도 됩니다. **다만 지금 채울 수 있는 값은 없습니다.**

- 사내 IP·서브넷·라우터·DNS는 사내에서 확인하거나 IT에 물어야 아는 값입니다. 모른다고 해서
  빈 칸을 억지로 채울 일은 아닙니다. **[저장]은 필수 칸이 다 차고, 저장된 값과 달라졌을 때만 눌립니다**
  (앞뒤 공백처럼 표기만 다른 것은 달라진 것으로 보지 않습니다)
- **사내 Wi-Fi에 연결하면 값이 자동으로 채워집니다.** 사내 Mac은 대개 이미 고정 IP로 구성돼 있어,
  앱이 그 값과 붙어 있는 Wi-Fi 이름까지 읽어 넣습니다. **설정 창을 열어 둔 채 연결하셔도 됩니다.**
  그 자리에서 칸이 차고 [저장]이 살아납니다
- **권한 설치는 지금 해두시면 됩니다.** 장소와 무관합니다 (설정 창의 권한 섹션)
- 값을 이미 받아 두셨다면 지금 입력하셔도 됩니다 (손으로 적은 값은 자동 입력이 덮지 않습니다)

그때까지 메뉴바 첫 줄은 `초기 설정하기` 로 남고 그 아래에 `- 사내 Wi-Fi 에 연결하면 채워짐` 이 붙습니다.
빠뜨린 것이 있다는 뜻이 아니라, **아직 값을 만나지 못했다**는 뜻입니다.

## 업데이트할 때 생기는 일

새 버전으로 바꾸면 두 가지가 따라옵니다. **둘은 같은 이유에서 나옵니다.** 이 앱에는 서명과 공증이 없어서
빌드할 때마다 코드 서명이 달라지고, macOS는 새 앱을 **이름만 같은 다른 앱**으로 봅니다
(처음 열 때 [Gatekeeper가 막는 것](../README.md#설치)과 같은 이유입니다). 앱에 문제가 생긴 것이 아닙니다.

**1. 위치 권한을 다시 허용해야 합니다**

Wi-Fi 이름을 읽지 못하게 되고, 메뉴 머리말이 `초기 설정하기` 로, 그 아래가 `- 위치 권한 미승인` 으로 바뀝니다.
설정 창의 **권한** 항목에서 **[허용 요청]** 을 누르면 승인 창이 다시 뜹니다
(한 번 거부하신 뒤라면 **[위치 권한 열기…]** 로 시스템 설정에서 켭니다). 그 한 번으로 원래대로 돌아갑니다.

**나머지는 그대로입니다.** 알림 권한은 앱의 **번들 식별자**에 매여 있어 남고,
전환 권한과 설정 값은 앱 밖(`/usr/local/…`)에 있어 앱을 바꿔도 영향이 없습니다.
**위치 권한만 앱의 서명에 매여 있습니다.**

**2. 로그인 항목은 그대로 켜져 있습니다**

앱을 바꿔도 자동 실행은 풀리지 않습니다. 위치 권한과 달리 로그인 항목은 앱의 **번들 식별자**에
매여 있어 서명이 달라져도 그대로입니다.

> 0.1.0 이전 버전에서는 앱을 바꿀 때마다
> **"'EXEM Wifi Switcher' 앱은 백그라운드에서 실행될 수 있습니다"** 알림이 한 번 떴습니다.
> 그때는 로그인 항목을 `~/Library/LaunchAgents` 에 놓았고 macOS가 그것을 백그라운드 항목으로
> 보았기 때문입니다. 지금은 로그인 항목으로 등록하므로 그 알림이 뜨지 않습니다.
> 예전 방식으로 켜 두셨다면 새 버전을 처음 실행할 때 자동으로 옮깁니다.

> 직접 빌드해서 쓰시는 경우에도 똑같습니다. `./scripts/build-app.sh` 로 다시 만든 앱은 서명이
> 달라지므로 위치 권한을 다시 허용해야 합니다.

**릴리즈 노트를 먼저 보세요.** 전환 권한(`sudoers`)이나 설정 파일 형식이 바뀐 버전은 앱만 바꿔 넣어서는
안 되고 설정 창의 **권한** 항목에서 **[설치]** 를 한 번 더 누르셔야 합니다. 그런 변경은
**릴리즈 노트 맨 위에 적습니다.** 적혀 있지 않으면 그럴 필요가 없는 버전입니다.

## 설치되는 항목 전부

이 도구는 `sudoers` 를 수정하고 로그인 항목을 등록합니다. 무엇이 어디에 놓이는지 숨기지 않습니다.

| 경로 | 소유·권한 | 무엇 |
|---|---|---|
| `/usr/local/libexec/exem-wifi-switcher/` | `root:wheel 0755` | 아래 두 스크립트를 담는 디렉터리 |
| `/usr/local/libexec/exem-wifi-switcher/apply` | `root:wheel 0755` | • `networksetup` 호출, **암호 없이 실행**<br>• 인자는 프로필 이름 1개, 화이트리스트 검증 |
| `/usr/local/libexec/exem-wifi-switcher/save-config` | `root:wheel 0755` | • 설정 파일을 제자리에 놓습니다<br>• **암호 없이 실행되지 않습니다** |
| `/etc/sudoers.d/exem-wifi-switcher` | `root:wheel 0440` | • `apply` 만 암호 없이 허용합니다<br>• 와일드카드 없이 인자 패턴을 길이별로 고정 |
| `/usr/local/etc/exem-wifi-switcher/` | `root:wheel 0755` | 설정 디렉터리 |
| `/usr/local/etc/exem-wifi-switcher/config.json` | `root:wheel 0644` | 사용자 설정. 사내 IP 값이 여기에만 저장되고 저장소에는 올라가지 않습니다 |
| (파일 아님. macOS 의 로그인 항목 기록) | 사용자 | • 로그인 시 자동 실행(선택), 설정 창에서 등록<br>• `SMAppService` 등록, 파일은 없습니다 |
| `~/Library/LaunchAgents/com.horbis.exem-wifi-switcher.agent.plist` | 사용자 | • **0.1.0 이전 버전**의 로그인 항목<br>• 새 버전 실행 시 자동으로 옮기고 지웁니다 |
| `~/Library/Preferences/com.horbis.exem-wifi-switcher.plist` | 사용자 | 앱이 남기는 설정값(자동 전환 켜짐과 꺼짐 등). 앱이 만듭니다 |

로그인 항목을 확인하고 끄는 경로는 [설치](../README.md#설치) 에, `save-config` 가 저장할 때마다
관리자 인증을 받는 이유는 [저장할 때 관리자 인증을 한 번 받습니다](#저장할-때-관리자-인증을-한-번-받습니다)
에 적어 두었습니다.

상위 디렉터리(`/usr/local`, `/usr/local/libexec`, `/usr/local/etc`)가 없으면 `root:wheel 0755` 로 만듭니다.
이미 있으면 건드리지 않습니다.

이미 설정 파일이 있으면 **내용은 그대로 두고 소유와 권한만 위 값으로 맞춥니다.**
(예전 버전은 `root:admin 0664` 로 놓았습니다. 그 상태에서는 admin 그룹의 아무 프로세스나 값을 바꿀 수 있습니다)

앱 자체(`EXEM Wifi Switcher.app`)는 두신 자리에 그대로 있습니다. 설치가 앱을 옮기지 않습니다.

지우는 방법은 [README 의 제거](../README.md#제거) 에 있습니다.

## 한계

- IPv4만 다룹니다. IPv6 구성은 건드리지 않습니다
- **Wi-Fi 서비스 하나만 다룹니다.** 설정의 `service` 에 적힌 네트워크 서비스(보통 `Wi-Fi`) 하나가
  전부입니다. 유선(Ethernet)과 VPN 구성은 읽지도 바꾸지도 않습니다
- **프록시와 검색 도메인은 바꾸지 않습니다.** 전환이 손대는 것은 IPv4 구성(IP·서브넷·라우터)과
  DNS 서버뿐입니다. 사내에서 프록시를 따로 설정해야 한다면 그것은 손으로 하셔야 합니다
- **화면에서 만들 수 있는 조합은 고정 IP 하나와 DHCP 하나뿐입니다.** 사내 프로필 하나와
  그 밖의 모든 곳에 쓰는 자동(DHCP) 하나면 되기 때문입니다.
  더 필요하면 설정 파일을 손으로 고쳐야 하고, 그 프로필은 설정 창에서 보이지 않습니다
  (메뉴에서 고를 수는 있습니다)
- **서명과 공증이 없습니다.** 내려받은 앱은 처음 열 때 한 번 막히고, 시스템 설정에서 허용해야 합니다.
  새 버전으로 바꿀 때마다 위치 권한을 다시 허용해야 합니다 ([업데이트할 때 생기는 일](#업데이트할-때-생기는-일))
- Wi-Fi 이름이 같은 다른 네트워크는 구분하지 못합니다 (BSSID를 보지 않습니다)
- 고정 IP 프로필은 DNS 서버를 반드시 지정해야 합니다 (비워서 DHCP DNS를 물려받을 수 없습니다)
- 설정을 바꿀 때마다 관리자 인증이 필요합니다. 관리자 계정이 아니면 저장할 수 없습니다
- **Intel Mac에서 Homebrew가 `/usr/local` 을 소유하고 있으면 설치할 수 없습니다.**
  `sudo` 는 규칙에 적힌 경로를 그대로 실행하므로, 그 경로를 사용자 권한으로 갈아 끼울 수 있으면
  임의의 코드가 무암호로 root 실행됩니다. 설치 스크립트는 이 상태를 감지하고 멈춥니다.

  이때 **`sudo chown root:wheel /usr/local` 을 실행하지 마세요.** Homebrew가 통째로 망가지고
  `brew` 로는 되돌릴 수 없습니다. Apple Silicon의 Homebrew는 `/opt/homebrew` 를 쓰므로 이 문제가 없습니다
