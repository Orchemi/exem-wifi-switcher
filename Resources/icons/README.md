# 아이콘

EXEM Wifi Switcher 의 아이콘 자산. **성격이 다른 두 묶음**이 들어 있고,
만드는 방법도 다르다.

| 묶음 | 무엇 | 원본 |
|---|---|---|
| `menubar/` | 메뉴바 상태 아이콘 3종 (템플릿 이미지) | 손으로 쓴 SVG |
| `app/` | Dock·Finder 용 앱 아이콘 | `app/make-vectors.py` 가 만든 SVG + `export.sh` 의 색 합성 |

PNG·`.icns` 는 전부 파생물이다. **PNG 를 직접 고치지 마라.**
원본(SVG / 생성기)을 고치고 `./export.sh` 를 다시 돌린다.

```bash
./export.sh          # 어디서 실행해도 된다 — 스크립트 위치 기준으로 동작
```

의존성은 ImageMagick 7 (`brew install imagemagick`) 하나다.
`.icns` 생성에는 macOS 기본 탑재 `iconutil` 을 쓴다.

## 1. 메뉴바 아이콘 (`menubar/`)

```
manual.svg  manual.png  manual@2x.png     사내 프로필(고정 IP) 적용 중
dhcp.svg    dhcp.png    dhcp@2x.png       DHCP 적용 중
error.svg   error.png   error@2x.png      전환 실패 / 헬퍼 미설치
```

접미사 없는 파일이 @1x(16px), `@2x` 가 32px 다.
macOS 는 1x·2x 두 배율만 고르므로 `@3x` 는 만들지 않는다 — 쓰이지 않는 파일이다.

### 지켜야 할 규약

메뉴바 아이콘은 **템플릿 이미지**다. macOS 가 알파 채널만 읽고,
메뉴바 배경(라이트/다크, 강조 상태)에 맞춰 색을 알아서 칠한다.

- **단색 검정 + 알파만.** 색·그라디언트·그림자를 넣으면 반전이 깨진다
- 스트로크를 쓰지 않고 전부 **아웃라인(fill path)** 으로 그렸다.
  스트로크는 크기를 바꿔도 굵기가 함께 변하지 않아 템플릿에 부적합하다
- 코드에서 반드시 템플릿으로 표시해야 한다:

  ```swift
  let image = NSImage(named: "manual")!
  image.isTemplate = true          // 에셋 카탈로그라면 Render As: Template Image
  statusItem.button?.image = image
  ```

### 세 상태를 어떻게 갈랐나

배지만 바꾸면 16px 에서 구분이 안 된다. **실루엣 자체를 다르게** 했다.

| 상태 | 형태 | 실루엣 | 왜 |
|---|---|---|---|
| `manual` | 지도 핀 | 아래가 뾰족한 물방울 | 주소가 한 자리에 **박혀** 있다. 동시에 "지금 회사에 있다" |
| `dhcp` | 끊긴 고리 + 화살촉 | 둥근 고리 | 주소를 그때그때 **새로 받아온다** |
| `error` | 느낌표를 파낸 삼각형 | 밑이 넓고 위가 뾰족 | 시스템 상태 아이콘은 배우지 않고도 읽혀야 한다 — 관례를 따른다 |

물방울(세로로 뾰족) / 원(둥긂) / 삼각형(가로로 넓음) 은 서로 가장 멀리 떨어진
실루엣이라, 곁눈질로도 갈린다.

세 아이콘은 광학적 무게를 맞춰 두었다 — 16px 에서 잉크가 차지하는 비율이
33.5% / 35.6% / 34.5% 로 거의 같다. 하나만 유독 진하거나 흐려 보이지 않는다.

### 확인 방법

`preview.png` 는 16px 원본을 8배로(픽셀 보간 없이) 늘려 라이트·다크 배경에
얹은 것이다. 실제 픽셀이 그대로 보이므로 여기서 판단하면 된다.
`preview-menubar.png` 는 다크 메뉴바에 셋을 나란히 놓은 시뮬레이션이다.

형태를 고쳤다면 **반드시 이 두 장을 다시 보고** 16px 에서 구분되는지 확인하라.

## 2. 앱 아이콘 (`app/`)

```
make-vectors.py       형태 생성기 (기하가 여기 다 있다)
tile.svg              스퀘어클 타일 실루엣
symbol.svg            심볼 (고리 + 화살촉 + 핀)
app-icon-1024.png     1024 마스터
AppIcon.icns          16~1024 전 사이즈 묶음
preview-app.png       256/128/64/32 대조
```

### 형태

심볼은 **메뉴바의 `manual`(핀) 과 `dhcp`(순환 화살표) 를 한 그림으로 합친 것**이다.
"고정된 자리를, 자동으로 갈아 끼운다" 는 앱의 한 줄이 그대로 형태가 된다.
고리 각도(302°→242°, 위쪽 60° 틈)와 핀 비율은 메뉴바 쪽과 같은 값을 쓴다.
다만 16px 에서 살아남아야 하는 메뉴바 쪽은 획을 더 굵게 쓴다 — 의도된 차이다.

타일 기하는 짐작하지 않고 **macOS 실제 아이콘(`Terminal.app`)의 알파를 실측**해
맞췄다: 캔버스의 80.5%(1024 중 824px), 코너 반지름은 변의 24.25%,
코너 초타원 지수 2.2(2.0 이면 정원호 — 즉 아주 약한 스퀘어클이다).

핀은 고리 안에서 위로 미세하게(고리 안반지름의 5%) 올려 두었다.
핀은 아래로 뾰족해 무게가 아래로 쏠리는데, 기하학적으로 정중앙에 놓으면
눈에는 살짝 처져 보인다.

### 색

저채도 슬레이트 네이비 한 계열, 명도 폭이 좁은 세로 2단 그라디언트다
(`#3E4F6B` → `#232D40`). 광택·안쪽 하이라이트·바닥 그림자 같은 겹은 쓰지 않았다.
그림자는 밝은 배경에서 타일이 묻히지 않을 만큼만 넣는다.

색을 바꾸려면 `export.sh` 상단의 `GRAD_TOP` / `GRAD_BOTTOM` 을 고친다.
형태를 바꾸려면 `make-vectors.py` 의 상수를 고치고 다시 돌린다:

```bash
python3 app/make-vectors.py && ./export.sh
```

### 왜 생성 이미지가 아니라 벡터로 직접 그렸나

처음에는 이미지 생성 모델로 시안을 뽑아 봤다. 구도 — 고리가 핀을 감싼다 — 가
쓸 만한지 확인하는 데는 도움이 됐지만, **채택하지 않았다.** 결함이 셋이었다.

- 화살촉이 뭉개져 의도하지 않은 곁가지가 생겼다
- 핀이 고리 중앙에서 밀려 있었다
- 타일이 macOS 스퀘어클이 아니라 그냥 둥근 사각형이었다

셋 다 정렬을 손보는 정도로는 못 고친다. 래스터 결과물에는 고칠 수 있는
**기하가 남아 있지 않기** 때문이다 — 고리 각도도 코너 곡률도 픽셀에 구워져 있어,
값을 바꾸는 게 아니라 다시 그리는 수밖에 없다. 이 아이콘은 16px 부터 1024px 까지
같은 형태를 유지해야 하고 메뉴바 쪽과 각도·비율을 공유해야 하므로,
**숫자로 표현되는 형태**가 필요했다.

그래서 `make-vectors.py` 에 기하를 상수로 두고 SVG 를 생성하는 쪽으로 갔다.
지금 고리 각도(302°→242°)와 타일 코너 지수(2.2) 를 한 줄 고쳐 다시 뽑을 수 있는 것이
그 결과다. 시안 이미지 자체는 판단을 마쳤으므로 레포에 남기지 않는다.

## 앱에 연결하기

아직 어느 타깃에도 연결돼 있지 않다. `.app` 번들을 조립할 때 이렇게 넣는다.

- `app/AppIcon.icns` → `Contents/Resources/AppIcon.icns`,
  `Info.plist` 에 `CFBundleIconFile = AppIcon`
- `menubar/*.png` → `Contents/Resources/` 에 그대로 복사.
  `@2x` 접미사 규칙 덕에 `NSImage(named:)` 가 화면 배율에 맞는 것을 고른다

에셋 카탈로그를 쓴다면 상태 아이콘 3종은 반드시
**Render As: Template Image** 로 지정해야 한다. 코드로 붙일 때는
`image.isTemplate = true` 를 빼먹지 마라 — 빼면 다크 메뉴바에서 검은 아이콘이
그대로 나와 보이지 않는다.
